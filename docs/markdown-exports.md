# Markdown export metadata

Markdown downloads begin with YAML frontmatter. bakerversity_export identifies the format version (1); content_source is editor because the download includes current editor content and current form values, including unsaved changes. It does not claim the file is the published version.

Lesson and course-page editors supply title, kind, course_slug, and available identifiers/settings. Saved lesson editors also supply the lesson slug, introduction, module, and learning settings. Assessment introduction downloads identify section as introduction and include grading settings; they are not exports of the question set. Generic embedded editors include only available context, not invented lesson titles or publication status.

Strings are quoted and escaped; empty/unknown values are omitted while false and zero are preserved. Metadata order is stable and exports have no changing timestamp. The existing Markdown body, footnotes, and component conversion remain unchanged. HTML and plain-text downloads are unaffected.

Markdown import strips frontmatter from the body and applies only supported fields on the current editing screen: title, introduction, estimated_minutes, activity_type, and is_required where those fields are available. Missing fields leave existing values unchanged. Course identity, module assignment, publication, ownership, grading, and course-wide settings are never applied. A compact “Imported · Not saved” notice provides an information icon when details are available. The Import details modal explains why source and course settings remain unchanged without listing those fields individually. Unavailable fields and invalid values appear separately in the modal, with a short cue in the notice when any could not be applied. Supported content still imports. Malformed YAML stops the import before any changes are applied. Imported changes remain unsaved until the author saves normally. Assets remain URL references, not bundled files. This is not a complete course backup.
